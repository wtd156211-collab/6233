# 日历重复规则引擎（RRULE 子集）

产品在评审会上提了个需求：日历要能一直往后翻，翻到什么时候都不卡。散会我才发现这事不好办——现在这套展开是一条一天往后推的，用户翻到第五年就开始卡，十万次以后的日期压根算不出来；加上上个月那次死循环把进程卡住的事故，我决定把这块重做。

范围写死：频率只做**天、周、月、年**四种，支持**间隔**（INTERVAL）、**次数上限**（COUNT）、**截止日期**（UNTIL），筛选支持**按星期几**（BYDAY）、**按月内第几天**（BYMONTHDAY）、**按月内第几个星期几**（BYSETPOS）。**时区和夏令时明确不做**，别顺手把没要求的都实现一遍。比原来多两件事：**取第 N 次**（N 可以很大，不能从第一次一条条数过去）与**求某个时间点之后的下一次**，都要快。用户还会临时改：某几次取消（EXDATE）、某几次挪到别的日子（moves），都有条数上限；**序号是对最终序列来说的，取消之后后面的日期要顶上来**。规则再离谱也不许转不出来，兜底见下。同一份规则跑两遍结果必须一样；标准库以外不许用，测试写在 unittest 里。

## 规则与语义

规则是 JSON：`{"freq":"monthly","interval":2,"count":12,"until":"2027-12-31","dtstart":"2026-01-01","byday":["MO","WE"],"bymonthday":[1,15],"bysetpos":[2],"exdates":["2026-03-01"],"moves":[{"from":"2026-05-01","to":"2026-05-02"}],"bymonth":[2]}`。

| 字段 | 语义 |
| --- | --- |
| `freq` | `daily` / `weekly` / `monthly` / `yearly`，只这四种 |
| `interval` | 间隔，正整数，缺省 1（每 N 天 / 周 / 月 / 年） |
| `count` / `until` | 次数上限与截止日期；`until` **当天算在内**（`<=`） |
| `byday` | 星期几（`SU`…`SA`）；周频里决定一周取哪几天，月/年频里作为筛选条件 |
| `bymonthday` | 月内第几天（1–31） |
| `bysetpos` | 在当期已筛出的日期里取第几个（1 起，负数从后往前），常用于「第 5 个星期五」 |
| `bymonth` | 年频里限定月份 |
| `exdates` / `moves` | 取消的日期；`from` 取消并追加 `to`。两者各**最多 1000 条**，超了报 `TOO_MANY_OVERRIDES` |

## 边界口径

- **某个月没有 31 号**：该月不产生日期（2 月、4 月都不会因为「少一天」而顺延到 30 号）；
- **BYSETPOS 取第 5 个星期几、但该月只有 4 个**：该月整体不产生日期；
- **2 月 29 日在平年**：跳过，只在闰年产生；
- **截止日期当天算在内**：`until` 等于某次发生时，这次保留；
- **取消与挪动的顺序**：先生成原始序列，再按 `exdates` 删除、按 `moves` 替换，最后**排序去重**；`count` 作用在最终序列上；
- **序号语义**：`取第 N 次` 的 N 是最终序列里的位置（从 1 开始），所以取消之后后面的日期会顶上来。

## 兜底与性能

- **兜底条数**：展开与「取第 N 次」最多扫描 **100000 个周期**；扫完仍没有结果就报 `error,NO_OCCURRENCE,searched=100000`，不许无限转下去、也不许卡住；
- 没有 `count` 与 `until` 时，序列在这个兜底上限处截至，`total` 就是上限内的大小；
- 「取第 N 次」与「求下一次」都要能在**很短时间内**返回（N 很大也不许线性数过去）——实现上要求按周期直接推算，而不是逐条枚举到今天。

## 输出格式

```text
case=case-1
note=每天一次 + 大 N（第 100000 次）
total=100000
first=2026-01-01
last=2299-10-16
periods=100000
query=nth,100000,2299-10-16
query=next,2030-05-05,2030-05-06
```

查询失败写成 `query=<kind>,<参数>,error,<错误码>,<说明>`；整条规则无解时只输出 `error,<错误码>,<说明>`。

错误码：`NO_OCCURRENCE`（兜底内排不出来，说明含 `searched=`）、`OUT_OF_RANGE`（序号超出序列长度）、`TOO_MANY_OVERRIDES`（取消或挪动超过 1000 条）。

## 样例

`samples/case-N.rule.json` 与 `samples/case-N.expected.txt` 一一对应：case-1 每天 + 第 100000 次；case-2 周一三五 + COUNT/UNTIL；case-3 每月 31 号；case-4 每年 2 月 29（平年跳过）；case-5 每月第 5 个星期五；case-6 取消与挪动后序号顶上来；case-7 永远排不出来的兜底；case-8 每两个月取每月第 2 个日期。
